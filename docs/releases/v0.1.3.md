# AntiFraud-KnowledgeHub v0.1.3 Release Notes

Status: **release-candidate notes**. The `v0.1.3` tag and GitHub Release are intentionally not created by this preparation task.

Comparison base: `v0.1.2` (`207aa898d6d7e96e8de3aa5f880a6aa45fa76fca`).

This release continues the early-stage `v0.1.x` line. It adds substantial optional AI-assisted and browser capabilities while preserving the deterministic risk engine as the authoritative anti-fraud result.

## Highlights

### Privacy-preserving browser risk-check prototype

- Added the first Chromium Manifest V3 extension prototype.
- Analysis is triggered only for explicitly selected text.
- The extension uses a fixed loopback API target with minimal permissions.
- Extension state is session-only.
- Added the deterministic no-write `POST /api/v1/analysis/preview` path so extension checks do not create `AnalysisRecord` rows.
- Added extension Node tests to CI.

### Provider-neutral AI assistance core

- Added a provider-neutral `llmassist.Provider` interface and assistance service.
- Deterministic `risk_score`, `risk_level`, matched rules, evidence and rule-derived recommendations remain authoritative.
- Provider input receives a deep-copied deterministic result so provider code cannot mutate the authoritative result.
- Added bounded timeout/cancellation/fallback behavior.
- Provider failure produces supplemental `unavailable` rather than failing or rewriting the deterministic result.
- Added bounded supplemental output validation.
- Tool/function calling, arbitrary URL retrieval, database access and rule mutation are outside the provider contract.

### OpenAI, Gemini and DeepSeek providers

- Added bounded OpenAI Responses, Gemini `generateContent` and DeepSeek chat-completions adapters.
- Added server-owned provider registry and runtime model selection.
- Added provider-specific credential validation and secret-safe failures.
- Added shared provider conformance tests.
- CI uses fake/injected HTTP and makes zero real paid-provider calls.

### Explicit controlled assisted-analysis transport

- Added default-off `POST /api/v1/analysis/assisted` for maintainer/operator use.
- Uses an independent server-side Bearer credential.
- Uses fail-closed Redis per-credential/global rate and cost admission.
- Strict bounded input is processed by the deterministic engine before exactly one selected assistance call.
- Provider failure after deterministic success returns HTTP `200` with the deterministic result unchanged and supplemental status `unavailable`.
- No automatic provider retry is performed.
- Assisted requests create no new `AnalysisRecord` and do not persist provider prompts, responses or hidden reasoning.

### Authenticated browser assisted-analysis bridge

- Added operator-provisioned high-entropy Browser Access Grants with digest-only server configuration.
- Added opaque one-hour Redis browser sessions with HttpOnly cookies.
- Added principal-generation revocation so disabling/removing a principal or incrementing its generation invalidates existing sessions.
- Added exact-Origin and derived-CSRF checks for state-changing browser routes.
- Added trusted-peer-aware pre-auth exchange limiting; forwarded client IP headers are ignored unless the direct peer is explicitly trusted.
- Added session-protected public profile metadata containing only bounded non-secret fields.
- Added `POST /api/v1/browser/analysis/assisted` with per-principal/global Redis cost admission.
- Browser callers may submit only `text` and a server-approved `profile_id`; provider, model, API key, base URL, endpoint, tools, retry and output budgets remain server-owned.
- Negative-path tests prove unauthenticated, Origin/CSRF rejected, rate denied, invalid request/profile and database-failure paths do not invoke a provider.

### Explicit Vue AI opt-in

- Added an optional AI-assisted section to the text-analysis UI while keeping the rule-engine result visually primary.
- Browser Access Grants are transient and are cleared from Vue input state after exchange attempts.
- CSRF state is held only in the current in-memory Vue runtime.
- The raw browser session remains inaccessible to JavaScript through the HttpOnly cookie.
- The server-provided third-party transfer disclosure is rendered immediately beside the explicit AI consent control.
- AI requests are never triggered automatically by page load, demo mode, deterministic analysis, text changes or session restoration.
- The browser-assisted client fails closed if its API base resolves cross-origin.
- The current single-profile UX fails closed if more than one approved profile becomes available; it does not silently choose one.
- Added a Browser Assisted Safety Test to CI to guard against browser credential persistence/exposure and accidental trust-boundary regressions.

### Documentation and sample-data improvements

- Expanded anonymized scam-case sample coverage and seed quality gates.
- Updated README, API, architecture and ROADMAP documentation to match the delivered controlled AI/browser capability.
- Closed the original optional LLM-assisted analysis parent task after mapping all original acceptance goals to live implementation and documentation.

## Security and privacy boundaries

The following remain release invariants:

- The deterministic risk engine is the sole authority for risk score, risk level, matched rules, evidence and rule-derived recommendations.
- LLM output is supplemental only and is not a definitive fraud verdict, rule approval authority or enforcement decision.
- Existing `/api/v1/analysis/text` and `/api/v1/analysis/preview` remain deterministic-only and never start calling an LLM merely because a provider is configured.
- All cost-bearing assisted-analysis transports are disabled by default.
- Provider API keys, the controlled maintainer assisted token and raw Browser Access Grants must never be embedded in the SPA or extension.
- The SPA does not persist Browser Access Grants or CSRF tokens in localStorage, sessionStorage or IndexedDB.
- CORS is not treated as authentication.
- Redis protection/state failures on assisted admission fail closed.
- Provider failures cannot suppress or rewrite a successfully computed deterministic result.
- No automatic provider retry is performed.
- CI makes no real OpenAI, Gemini or DeepSeek request.

## Configuration and upgrade notes

### Existing deterministic deployments

No AI/browser feature is enabled automatically by upgrading from `v0.1.2`.

A deployment that keeps the new feature flags at their defaults continues using the deterministic API and dashboard without provider credentials.

### New optional server configuration

See `.env.example` for the complete current contract. Major new groups include:

- `LLM_ASSISTANCE_*` and provider-specific server-side API keys;
- `LLM_ASSISTED_ANALYSIS_HTTP_*` for the controlled maintainer transport;
- `BROWSER_ASSISTED_*` for the controlled browser session and assisted-analysis bridge;
- Browser Session exchange and assisted per-principal/global Redis limits.

Do not copy provider keys, the maintainer assisted token or raw Browser Access Grants into `VITE_*` variables or browser source.

### Database and Redis

There is no new database schema/migration requirement in the `v0.1.2..v0.1.3` release delta.

The new browser/AI protections use Redis for opaque session state and bounded rate/cost admission. Deployments enabling these optional features therefore require a healthy Redis backend; protection failure is intentionally fail-closed.

## Compatibility

- Existing deterministic text analysis remains available at the same route and response authority model.
- Existing deterministic preview behavior remains provider-free.
- Existing community submission/review/publication behavior from `v0.1.2` remains in place.
- New AI/browser routes are additive and default-off.
- No public user account/OAuth/RBAC system is introduced by the browser bridge.
- Frontend `package.json` and browser-extension `manifest.json` component versions remain `0.1.0`; they are not used as the repository release tag in this release. Extension packaging/versioning should be changed only when store/distribution work is intentionally undertaken.

## Known limitations / intentionally future work

The release does **not** claim completion of:

- broader `v0.2 Community Rules` work such as rule versioning/history and per-rule changelog presentation;
- a public contributor/user identity, OAuth or general RBAC subsystem;
- anonymous public cost-bearing LLM access;
- a Vue multi-profile selector for deployments intentionally enabling multiple server-approved profiles;
- browser-extension store packaging or cross-browser distribution;
- browser-extension LLM-assisted flow;
- persisted LLM conversation/history or provider-response audit storage;
- a definitive fraud/not-fraud AI verdict.

The Chromium extension remains a local prototype using fixed loopback integration.
