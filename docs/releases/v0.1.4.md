# AntiFraud-KnowledgeHub v0.1.4 Security Patch Release Notes

Status: **release-candidate notes**. The `v0.1.4` tag and GitHub Release are intentionally not created by this preparation task.

Comparison base: `v0.1.3` (`e3cff12a2b5954cf38066491b71a4da011231574`).

This patch release is intentionally narrow. It contains a security hardening change to the default public Category, Risk Rule, and Scam Case HTTP surface plus the design, regression tests, and public API documentation required to keep that boundary reviewable. It does not add a new user-facing feature set.

## Security fix

### Default public persisted-content API is now read-only

The default public API no longer registers direct create, update, toggle, or delete routes for persisted Category, Risk Rule, or Scam Case content.

The routes retained for these resources are:

- `GET /api/v1/categories`
- `GET /api/v1/categories/{id}`
- `GET /api/v1/rules`
- `GET /api/v1/rules/{id}`
- `POST /api/v1/rules/validate` — validation only, with no persistence side effects
- `GET /api/v1/cases`
- `GET /api/v1/cases/{id}`

Ten former direct mutation method/path pairs are no longer registered by the production router:

- Category: `POST`, `PUT`, and `DELETE` direct mutation routes;
- Risk Rule: direct `POST`, `PUT`, `PATCH .../toggle`, and `DELETE` routes;
- Scam Case: `POST`, `PUT`, and `DELETE` direct mutation routes.

Under the current Gin router configuration, requests to those removed exact method/path pairs receive `404 Not Found` because there is no matching handler. The security contract is route absence and zero persistence mutation rather than a particular JSON error body.

### Why this patch is security-sensitive

Before this remediation, the default router registered direct persisted-content mutation handlers without an authentication or authorization boundary. Risk Rule mutation was the most significant impact because persisted `RiskRule` objects are executable deterministic risk-engine input. An unauthenticated caller could therefore have altered, disabled, or removed rule content outside the controlled contribution workflow and affected authoritative deterministic scoring/evidence behavior.

Category and Scam Case direct mutation were affected by the same public-router boundary problem and are also removed from the anonymous persisted-content surface.

The patch does not publish exploit commands, payloads, or automation for abusing the previous behavior.

### Controlled Rule workflow remains the write boundary

The existing default-off Rule Submission -> Review -> Publication workflow is unchanged and remains the current HTTP mutation path for Rules.

It continues to use purpose-specific, independently configured credentials and its existing validation, replay/concurrency, audit/provenance, and negative security controls. This patch does **not** reuse submission/review/publication tokens as general administrator credentials.

CORS is not treated as authentication or authorization.

No general user account, OAuth, administrator session, or RBAC subsystem is introduced by this patch.

### Direct mutation handlers removed, not merely hidden

The direct Category/Rule/Case HTTP mutation handlers were removed along with their route registrations where they had no remaining approved HTTP caller. This reduces the chance that a future router edit casually re-exposes the old mutation surface.

Repository seed/import mechanisms and the separately controlled publication service remain independent persistence mechanisms.

## Regression protection

A production-router security test now exercises all ten removed mutation method/path pairs.

For every prohibited request the test:

1. starts from known Category, Risk Rule, and Scam Case persistence state;
2. sends a syntactically plausible request through the same router construction used by the server;
3. requires the route to be absent (`404` under the current router configuration);
4. re-reads persisted Category/Rule/Case state;
5. asserts that no content was created, updated, toggled, or deleted.

Positive compatibility checks also verify that:

- public Category/Rule/Case reads remain available;
- `POST /api/v1/rules/validate` remains available;
- rule validation has zero persistence side effects.

Historical tests that previously required anonymous direct Rule creation were migrated rather than weakening the new security boundary. Category validation remains covered through the surviving no-write validation endpoint, and draft `Enabled` mapping semantics remain covered directly at the domain-mapping level.

## Compatibility impact

This is an intentionally security-breaking patch for any client that relied on anonymous direct Category/Rule/Case mutation routes.

There is no deprecation period for an authorization-bypass surface. Deployments or scripts that used those routes must stop doing so rather than re-enable them locally without an independently designed authentication/authorization boundary.

Unaffected behavior includes:

- Category/Rule/Case public reads;
- no-write Rule draft validation;
- deterministic text/preview analysis;
- controlled Rule Submission / Review / Publication;
- optional assisted-analysis and Browser Session functionality;
- Vue read/analysis behavior;
- Chromium extension behavior.

The current Vue clients did not depend on the removed direct mutation routes, so no frontend behavior change is required for this patch.

## Upgrade notes

### Database

No database schema migration is required for the `v0.1.3..v0.1.4` delta.

This patch does not change persisted model definitions, AutoMigrate ordering, indexes, Rule submission/review/publication schemas, or audit-event schemas.

### Configuration

No new required environment variable is introduced.

Existing AI/browser features remain default-off according to their existing configuration contracts. No provider key, Browser Access Grant, or controlled workflow credential behavior changes in this patch.

### If you previously used direct CRUD as an operator tool

Do not restore the removed anonymous routes behind CORS and do not generalize existing workflow tokens into administrator credentials.

For current maintainer-managed content, use reviewed repository seed/data changes and the existing controlled Rule contribution workflow where applicable. A future browser/API administrator mutation capability, if needed, must be separately Design First with authentication, authorization, auditability, bounded inputs, concurrency semantics, and negative security tests.

## Security invariants preserved

- The deterministic risk engine remains the sole authority for `risk_score`, `risk_level`, matched rules, evidence, and rule-derived recommendations.
- Persisted rules cannot be anonymously modified through the default public CRUD surface.
- LLM output remains supplemental only and cannot approve/publish/mutate rules or replace deterministic authority.
- Provider credentials and privileged controlled-workflow credentials remain server-side.
- CORS is not authentication.
- Existing cost-bearing assisted-analysis transports remain default-off and retain their Redis/session/cost controls.
- CI uses fake/injected provider HTTP and performs no real paid-provider request.

## Release scope

The expected release delta from `v0.1.3` consists only of:

1. the frozen public-content mutation security design;
2. the P0 runtime/test/API-documentation remediation;
3. these v0.1.4 release-readiness notes and the README release-notes link update.

No Rule Versioning/History feature implementation is part of this patch. Broader `v0.2 Community Rules` work remains future work after the security patch is published.

## Known limitations / intentionally future work

This patch does not add:

- a public contributor identity system;
- OAuth or general RBAC;
- a browser/API administrator CRUD surface;
- Category or Scam Case contribution workflows;
- Rule Versioning/History or per-rule changelog UI;
- a Vue multi-profile assisted-analysis selector;
- extension store packaging or cross-browser distribution.

The existing v0.1.3 AI/browser limitations remain unless explicitly changed by a later release.

> v0.1.4 is a focused security patch that removes unauthenticated direct Category, Risk Rule, and Scam Case mutation routes from the default public API.
